# yyl-video-prompt：导演式 AI 视频提示词

## 定位

把任何内容变成**能直接提交生成**的视频提示词。先按脚本风格选**档位**，两个档位共用生产层，画面层和表演层各有各的写法：

| 层 | 解决什么 |
|---|---|
| 生产层（共用） | 脚本拆成生成单元；每段选生成模式、参数、参考图；段与段接得上 |
| 画面层 | 人物、道具、场景空间、镜头、风格光影、声音、硬约束 |
| 表演层 | 短视频：一句可见动作 + 一个表情节点。电影精品：八维公式、AU、情绪递进、反应链 |

原则：**日常动作轻量写，关键时刻细写，AI 容易出错的地方重点写。**

## 第 0 步：选档位

| | 短视频档 | 电影精品档 |
|---|---|---|
| 平台 / 用途 | 抖音、小红书、视频号、快手、Reels；剧情片段、街拍、氛围短片、角色小故事、竖屏短剧 | 剧情短片、精品剧、文艺片段落 |
| 节奏 | 一镜到底每 2 秒一个事件节点，或多分镜每镜 2–5 秒 | 4–12 秒一镜，固定机位或极慢推近 |
| 靠什么推进 | 动作事件、运镜、空间和声音、视觉反差 | 表演：情绪递进、对白、对手戏 |
| 表演写法 | 一句可见动作 + 表情变化，人话，不用 AU | 八维公式 + AU 辅助 + 反应链 |
| 结构 | 写法 A 一镜到底（《丹眉》式）/ 写法 B 多分镜（赛博原子式） | 全文地图 / 人物一致性 / 分镜时间轴 / 核心要求…… |
| 来源 | AI-video-prompt《丹眉》+ mx-shell-prompt 赛博原子 | yyl-video-prompt v1 |
| **先读** | [modes/short-video.md](modes/short-video.md) → [examples/short-video.md](examples/short-video.md) | [modes/cinematic-drama.md](modes/cinematic-drama.md) → [examples/cinematic-drama.md](examples/cinematic-drama.md) |

**判断规则**：

1. 用户说了平台或风格 → 照用户说的。抖音、小红书、快节奏、短视频走短视频档；精品剧、电影感剧情、慢节奏、表演走电影精品。
2. 没说时看脚本：有多句对白，加上情绪转折、对手戏，而且是同一场景 → 电影精品；其余 → 短视频。
3. **竖屏短剧** → 短视频档，借电影档的对白嵌入和反应链（见短视频档文末）。
4. 说不清 → 短视频档，并在第 3 步的确认消息里说明「可以切到电影精品档」。
5. **合成 / 编辑类任务**（把 A 放进 B、只改背景）两档都不用，按 [tool-adapters.md](references/tool-adapters.md) 末节的极简写法。

一个项目里不同段可以用不同档位，例如开场钩子走短视频，正戏走电影精品。

**选定档位后，先读该档的 `modes/` 文件和对应示例，再动笔。**

## 工作流

### 第 1 步：读输入，定三件事

1. **目标工具和模型**：决定单段时长上限和素材引用写法，见 [tool-adapters.md](references/tool-adapters.md)。用户没说就按当前项目默认；项目也没有默认，就用 `Seedance 2.5 | 720p | 16:9`。
2. **影像基调**：电影摄影 / 手机实拍 / 动画。手机实拍不写「电影感、IMAX、大片、4K」。
3. **参考素材**：有素材就给每张定一个任务；没有就写清该准备什么图，或者改成纯文生。

一句话想法：视为单段，直接补全，跳过第 3 步的确认。

### 第 2 步：拆段

按地点、时间、情绪大转折、视角切换、单段时长上限来切。段尾写清结束状态，下一段从这里接。细则见 [REFERENCE.md](REFERENCE.md)「二、分段」，各档的镜头数见 `modes/`。

### 第 3 步：导演判断（唯一的确认门）

逐段判断：哪里轻写，哪里细写，AI 会在哪里出错。多段或方向有歧义时，**用一条消息**交给用户：

```text
档位：短视频（一镜到底）——理由一句话；想要慢节奏表演可以切到电影精品档。
我拆成 N 段：
段1（0–15s）：[一句话节拍]｜[生成模式]｜[需要的参考图]
段2（……）：……

我的判断：
- 段1 [某个时刻]：我打算 [处理]，观众会感觉 [效果]；另一个方向是 [备选]。

确认就说「直接写」；要合并、拆开或改方向直接说。
```

如果只有一段、意图清楚，就跳过这一步直接写。用户答不上来的地方，给两三个选项并说清效果，不要让用户填表。

### 第 4 步：逐段写

用该档的结构写（见 `modes/`），照着该档示例的密度和语气来。示例是标杆，只拿来学，不要按通用规则去「改进」它们。

### 第 5 步：自检后交付

过一遍下面的共用自检和该档的专用自检，可以跑 `python3 scripts/prompt_builder.py --validate <文件>`。交付后问一句：要调整分段、换档位，或者加重/减弱某处吗？

## 每段的外壳（两档通用）

````markdown
## 段1：[一句话节拍]（0–15 秒）

档位：短视频（一镜到底 / 多分镜） 或 电影精品
生成模式：[纯文生 / 首帧图生 / 首尾帧 / 多图参考 / 全能参考 / 视频编辑]
模型参数：[模型] | [分辨率] | [画幅] | [时长]
参考素材：
图片1：[唯一任务]——锁定 [脸 / 发型 / 服装 / 比例……]；不使用 [背景 / 其中的人物……]
（纯文生写「无」；缺图时写清该准备什么图）

提示词：
```text
[按该档的结构写]
```

段尾状态：[姿势、位置、构图——下一段从这里接]
````

提示词块里的素材引用要换成目标工具的写法（`@图片1` / `参考图1` / `{{Node "节点名"}}` / `@图像1`）。

## 核心规则（两档通用）

1. **每段自包含**。生成工具没有跨段记忆。人物锁定、场景、光线、手里的道具、上一段的结束状态，每段都要写全，不写「同上」「沿用上一段」。长相和衣服交给参考图锁定，文字里不重复描述。
2. **一张参考图只承担一个任务**。只写「参考图片」等于没写，必须写清锁定什么、不用什么。引用写法跟着工具走：LibTV 必须写 `{{Node "节点名"}}`，纯文本的「图片1」无效。
3. **时间码是动作预算**。时间窗连续、不重叠，一个窗口只放一个核心动作。关键事件写到具体秒。最后一拍留 0.5 秒余量，因为模型的最后一拍容易偏晚。
4. **首帧是第一个动作发生前的状态**。要第 2 秒架腿，首帧就必须双腿并拢。
5. **人物不能悬空**。每个受力部位都写清支撑：背靠什么、坐在哪、脚踩在哪。每个动作写起因和收尾。
6. **情绪写成可见动作**，不写孤立的情绪标签（例如「她很悲伤」）。短视频写一个表情节点；电影精品写完整的递进过程。
7. **对白嵌在时间码里**，不要把台词贴在最后。
8. **只写最重要的东西**。描述过度会让模型把本该在画面内部的元素提升到整个画面上。
9. **基调词要和基调匹配**。手机实拍不写「电影感 / 高清 / 大片 / 4K」。电影摄影要写具体的摄影机、镜头、胶片。风格参考最多 1–2 个。
10. **默认无背景音乐**，只保留同期声。用户要配乐才写。

## 共用自检

- [ ] 档位选对了，并且读过该档的 `modes/` 文件和示例
- [ ] 每段时长不超过工具上限
- [ ] 每段自包含，没有「同上 / 沿用上一段」
- [ ] 每张参考图只有一个任务，锁定项和排除项都写了；正文引用的编号都在参考列表里；引用写法匹配目标工具
- [ ] 动作有支撑点和前因后果；首帧是动作发生前的状态
- [ ] 声音有环境声底和事件音；没有 BGM（除非用户要求）
- [ ] 硬约束用正面句写死主体占比、空间逻辑、动作顺序；否定项只针对已知失败
- [ ] 段尾写了结束状态
- [ ] 过了该档的专用自检
