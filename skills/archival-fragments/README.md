# Archival Fragments — 档案剪贴风格短片

给一个想法或一份文案，产出一条完整短片：满幅象牙纸 + 单色印刷黑白 + 单一暗砖红，
镜头用 MiniMax H3 **首尾帧**驱动，配音用 Fish Audio，成片用 ffmpeg 合成。

**从一个空文件夹就能走完全流程**——装依赖、验凭据、写文案、拆分镜、生成、合成。

风格溯源自 MiniMax《ARCHIVAL FRAGMENTS》发布片的逐帧拆解，工作流是重新设计的：
原片用文生视频，本 skill 用首尾帧，可控性高一个量级。
已用一条 67.3 秒 / 34 镜的真实成片验证，34 镜一次通过。

![风格参考](assets/style-reference.png)

## 需要准备的三样

| 工具 | 用途 | 怎么拿 |
|---|---|---|
| **ffmpeg** | 量时长、变速、拼片、混音 | `brew install ffmpeg` |
| **LibTV CLI** | 调 MiniMax H3 出视频、Seedream 出图 | LibLib 官网下载，装完 `libtv login web` 登录 |
| **Fish Audio** | 合成旁白 | 官网建 API Key，连同音色 id 写进工作目录的 `.env` |

Skill 会逐项验，包括**真的合成一句测试音频**。详见 `references/00-setup.md`。

## 怎么用

新建一个空文件夹，`cd` 进去，跟 Agent 说：

> 用 archival-fragments 做条片子

它会先检查环境，缺什么告诉你怎么装；全绿之后让你给想法或文案。

## 三条硬约束

**1. 每一镜的画面必须不同。** N 个镜头需要 N+1 张各不相同的关键帧。
"相邻两镜共用同一张图"指第 1 镜尾帧 = 第 2 镜首帧这**一个接点**，不是整片共用一张图。
`assets/style-reference.png` 只给人看，**永远不要**作为生成输入。

**2. 故事、画面、节奏必须逐镜拆好，拆完先给用户过目。** 改一张逐镜表 5 分钟，跑完再改 4 小时。

**3. 具象优先。** 每句话找一个观众不用想就懂的通用符号——世界地图+图钉、天平、台阶、一大堆实物。
全片收敛到 2–3 个符号。抽象几何图形观众看不懂。

## 流程

```
0. 环境准备      装依赖 → 验登录 → 验 API → 全绿才继续
1. 想法→文案     说出主张 → 写短句文案 → 配音量时长
   拆故事        找贯穿符号，收敛到 2–3 个
   拆画面        每句 2–3 镜，每镜一个不同的具体画面
   拆节奏        按配音时长分配镜长
   ⏸ 逐镜表给用户过目
2. 关键帧链      N+1 张各不相同的图 → 出图 → 逐张审
3. 运动句        每镜一句话，说清镜头怎么动、什么在变
4. 排节奏        权重分配
5. 生成合成      先跑 2–4 镜确认 → ⏸ → 全量串行 → 变速拼片 → 混配音
```

## 耗时与成本

| 环节 | 耗时 |
|---|---|
| 关键帧 | 约 45 秒/张，35 张约 25 分钟 |
| 镜头 | **5–9.5 分钟/镜**，按 9 分钟排期。34 镜约 4.5 小时 |
| 配音 + 拼片 | 几分钟 |

**并发上限是 1**，必须串行。H3 最短只能生成 5 秒而每镜实际只用 1–3 秒，
素材/成片比约 **2.5×**——这是目前最大的一笔浪费。
