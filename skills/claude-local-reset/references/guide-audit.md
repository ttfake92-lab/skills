## 采用的补充（原有，v4 起生效）

| 范围 | AI 能做的动作 | 保留的边界 |
| --- | --- | --- |
| 网络测试 | 在用户常用的本地浏览器/profile 运行检测、记录完成时间与标签、交叉核对，再生成质检结果 | 远端网页抓取与全新隔离浏览器不能代表用户原 profile |
| 环境上下文 | 只读获取系统时区、Node 进程时区、`TZ` 覆盖和已配置的隐私开关 | 不改时区、定位或遥测；不开关推断封号风险 |
| 使用同一浏览器 | 确认本次检测 profile，提示后续登录链接在同一 profile 打开 | 不代填登录信息、不记录 OAuth 链接、验证码或 cookie |
| 账号后续 | 给出 Active sessions、Usage、隐私、申诉、导出资料入口 | 默认不进入账号页面；用户按需自行查看，不自动登出其他设备或提交表单 |
| 数据保护 | 保留本地归档、回滚入口与操作完成状态；生成本机私有回执 | 不上传备份、不为"看起来干净"删项目、skills 或 hooks |
| 完成反馈 | 自动生成并打开 HTML，缺项和失败仍交付回执 | 演示、未测、部分完成都明确标记 |

不把文中的付费节点、办卡、订阅节奏或个案成功率变成自动任务。城市/ASN、时区、第三方评分与限额都是不同问题；清理本地文件也不能验证服务器设备关联。不要自动改系统定位、伪装硬件或修改客户端二进制。

## 独立核实后的处理

- [Claude Code 环境变量](https://code.claude.com/docs/en/env-vars) 支持自定义入口及官方云供应商；发现 `ANTHROPIC_BASE_URL` 不等于发现废弃中转。继续脱敏列出、按实际用途判断。指南同时保留社区复盘结论：把订阅长期接到第三方入口属于高发被封情形，两者不矛盾——一个是"存在即违规"的误判，一个是"长期接订阅"的风险。
- [Data usage](https://code.claude.com/docs/en/data-usage) 确认非必要流量开关属于隐私偏好，关闭部分开关还可能影响功能旗标与 Remote Control。指南给出官方开关示例，但仅观察当前值，不能标成"防封通过"。
- [Active sessions 官方说明](https://support.claude.com/en/articles/13124001-managing-your-active-sessions) 说明查看与终止会话的效果。回执给出入口，不自动终止或把尚未查看的会话标为正常。
- [官方申诉与导出说明](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals) 给出账号被限制时的下一步。用户自行登录后处理；报告不自动提交。
- [官方退款说明](https://support.claude.com/en/articles/12386328-request-a-refund-for-a-paid-claude-plan) 写明除条款规定或法律要求外付款不退。指南据此把"付款先想退款路径"放在渠道选择之前，App Store 退款入口为苹果官方页面。
- [IPLeak](https://ipleak.net/) 已提醒旧 WebRTC Network Limiter 的时效性；[Chrome privacy API](https://developer.chrome.com/docs/extensions/reference/api/privacy) 仍定义 WebRTC IP 处理策略。把旧扩展降为待核实的历史选项，不能默认安装或假定当前 Chrome 兼容。
- [mihomo TUN](https://wiki.metacubex.one/config/inbound/tun/) 的劫持限制仍适用：不能把 TUN 开关直接换算成 DNS/UDP 无泄漏。指南的 TUN 设置步骤标注为社区经验，检测仍以 BrowserLeaks/Net.Coffee 实测为准。

用户额外要求的 CN/HK 地区标签与 Net.Coffee 两项检测，作为本 skill 的明确验收条件；页面写"用户设定的地区标准"和"第三方测试结果"，不改写成 Anthropic 官方黑名单规则。
