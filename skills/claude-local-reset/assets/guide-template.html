Claude 防封号指南

先按自己的情况准备，再让 skill 检查。账号操作由你完成，环境质检交给 AI。

这份指南帮助减少配置错误、识别异常；不能保证账号不被限制，也不能清除服务端记录。先核对官方地区要求，其中包含实际所在地和组织条件，出口 IP 的旗帜通过不代表满足使用资格。账号受限走原账号官方申诉。

本页步骤分两类标注：官方 可在官方政策或文档查证；社区经验 来自社区复盘（以 2026-10 社区长文为主），不是官方规则，也无法保证效果。风控更像一套多维打分系统：时区撕裂、WebRTC/DNS 泄漏、终端代理残留、设备共用任何一项异常都会叠加，单个信号不一定立刻出事，几条叠在一起过了线，号就没了。

我从未使用过 Claude →确认资格、固定时区与出口、准备专用浏览器；无需清理旧身份。 我曾被封号或限制 →先分清是哪种问题，保留资料、申诉并处理退款；环境检查不能解除封禁。
与 AI 配合的手动准备环境准备：时区·出口·TUN·自检账号与支付做完后，调用 skill 质检日常注意事项出发前清单

路径 A · 第一次使用

先准备使用环境，再自行注册登录

  1. 核对使用资格与官方入口。官方

    查看上方官方地区页面；条件不满足时，本指南没有提供绕过方案。网页从 claude.ai 进入，桌面版从 官方下载页 获取。不要把账号密码输入到不明镜像或代注册页面。

  2. 把时区和出口先固定下来。社区经验

    按环境准备把电脑和手机的时区改成同一个支持地区（东八区常用 Asia/Taipei），并选定一个固定出口节点。注册、登录、付款、日常使用全程走同一条线路；不要一边注册一边切节点。

  3. 选定日后实际使用的浏览器与 profile。你来做

    最好单独建一个浏览器资料（Chrome 右上角头像 → 添加），只用来登 Claude；单号不需要指纹浏览器——使用条款禁止的恰是多账号规避。后续检测、验证邮件和登录都使用这个 profile，确认当前是自己的 profile。无需为了首次使用清空浏览器、删除钥匙串或运行本地重置。

  4. 完成登录前自检，再做一次质检。AI 检查

    先做登录前 5 项自检，再复制质检提示词。只做检查；缺失项目会标为未检测。关键网络项未通过时先排查，不能把绿色分数当作注册保证。

  5. 自行完成注册、验证与首次登录。你来做

    在官方页面按提示操作，邮箱、验证码、密码和付款信息由你输入。验证邮件要在同一个代理环境、同一个专用浏览器里点开——环境配得再干净，在日常浏览器里点一下 Claude 的链接，真实 IP 就交出去了。登录后确认账号和服务提示；网络回执不验证账号是否可用。

  6. 注册后先按订阅节奏走。社区经验

    新号前几天用 Free 正常聊、写点小东西，不要立刻绑卡、开 Max 或接 CLI 高并发；具体节奏见账号与支付。后续切换网络或浏览器配置时，按实际变化重新检查。

路径 B · 曾被封号或限制

先分清是哪种问题，再决定处理顺序

你看到的通常是先做什么
回复突然变短、复杂问题答得敷衍、明显变慢（俗称“降智”）出口可能已被标记，还没到封号按环境自检先查出口 IP；是机房归属就先换出口，别急着换号
额度用完、五小时 / 每周限制限额，不是封号查 Usage 的重置时间，等到再继续
服务繁忙、系统错误平台故障看官方状态页，稍后重试
清 Cookie 后仍提示 disabled / restricted账号被限制走下面的申诉流程
提示违反 usage policy / 登录地区不受支持条款或地区问题申诉并处理退款；不要在同一环境秒开新号
  1. 记录原始提示，确认遇到了哪种问题。你来做

    保留提示文字、发生时间与官方邮件。明确的封禁或停用通知需要走账号处理流程。官方透明度报告显示申诉推翻比例很低，环境做在前面比事后申诉划算。

  2. 使用原账号走官方申诉。官方

    按官方申诉说明登录原受限账号，在受限页面打开申诉表。申诉只写事实：账号邮箱、提示原文、开始时间（带时区）、用的是网页 / Claude Code / API；简短可核查，别编故事。同一页可先导出账号数据，再决定是否删除。只是收到警告、还没封：按官方说明邮件说明情况。不要把创建新账号或删除本地 ID 当作解除封禁步骤。

  3. 立刻处理退款。你来做

    App Store 订阅去 reportaproblem.apple.com 申请；官网订阅走 claude.ai 左下角头像 → Get help → Send us a message → Claude Refund Request。申请退款不会自动取消续费，记得同时取消。官方政策是除条款规定外付款不退，违规封号基本不退，所以付款方式的选择见账号与支付。

  4. 申诉期间可以做只读排查。AI 检查

    复制下方提示词：AI 可检查配置和网络，并交付回执；不会代你提交申诉、登录或清理。本地归档与服务端账号状态分别记录，不能用“文件已处理”替代“账号已恢复”。

  5. 恢复后，仅修复仍存在的具体问题。按需执行

    如果账号已恢复，却仍有旧登录缓存或客户端故障，先让 AI 预览候选路径和影响。保存备份、退出相关 Claude 会话，再明确选定要修复的范围。仅检查时不要执行重置；不要把旧登录存储整份复制回新状态。也不要马上用同一台没清理过的电脑开新号硬冲——用新号绕过封禁本身就是条款违规。

曾被限制：先做只读排查

在安装了此 skill 的 AI 工具中发送。原账号申诉由你自行处理。

$$claude-local-reset
我曾遇到 Claude 账号限制。请先只读排查本地配置与网络，保留现有账号和文件，不执行重置或修复。使用我实际登录 Claude 的本地浏览器及 profile；无法确认的项目标为未检测。完成后生成含防封号指南入口的 HTML 质检回执，并在当前工具允许时打开。

两条路径都适用

与 AI 配合的手动准备

  1. 说明现在的实际网络状态。

    让 AI 知道是直连、系统代理还是 TUN，以及预期出口国家（知道才填）。保持检测期间的网络状态一致；不要一边测试一边切节点。时区与出口的长期设置见环境准备，那是为了消除环境自相矛盾的主动配置，不是为了对齐检测页旗帜的临时伪装。未知项可以让 AI 检查。

  2. 打开正确的浏览器与 profile。

    关闭其他用途的检测窗口，保留实际使用 Claude 的窗口。告诉 AI“用当前这个浏览器和 profile 检查”。登录授权、验证码和系统权限弹窗由你处理；检测页无需授予麦克风或摄像头权限。

  3. 用过中转时，说明你现在想走哪条路径。

    如果曾用镜像、Claude Code Router 或自定义网关，告诉 AI 你是要使用官方服务，还是保留合法且主动配置的网关。AI 检查 ANTHROPIC_BASE_URL 等路由候选，并脱敏报告。自定义地址存在只表示需要核对，不能直接认定违规；但把订阅长期接到第三方入口，属于社区复盘里明确的高发被封情形，见日常注意事项。

  4. 修复前记下原值，修复后新开终端。

    只有确认某条配置是残留，才针对该条处理；先保存原文件和网络设置。不整份删除 ~/.claude/settings.json、shell 文件或浏览器数据。修改 shell 配置后，旧终端仍可能保留变量，需要在新终端复测。

检测失败时怎么处理：DNS、WebRTC、IPv6 与代理
  • DNS：先核对检测确实完成，再检查所用网络工具的 DNS 开关、路由与接管配置。Mihomo/Clash 用户可检查 TUN 中的 dns-hijack 是否按实际配置生效；“开了 TUN”不能替代测试。公共 DNS 的地理标签可能与出口不同，先核对路径。
  • WebRTC：让 AI 比较检测页的公网候选与出口，不把私有地址或 mDNS 当成真实公网泄漏。需要修改浏览器设置时先记原值；不自动安装过时扩展。关闭 WebRTC 可能影响通话，且测试禁用会记为“未检测”，不能冒充“已完成且未泄漏”。
  • IPv6：只在确认 IPv6 未被预期路径接管时决定修复范围。优先核对现有工具的 IPv6 配置；选择关闭系统 IPv6 时须针对实际 Wi-Fi/网线服务并保存原值。单次 IPv6 查询失败不证明它已关闭，也不证明没有泄漏。
  • 系统代理：macOS 的代理值为 1 表示开启。如果你主动用系统代理，它可能是正确配置；不能一律关闭。纯 TUN 或直连模式下出现开启值，再核对是否为残留。
  • 中转与配置：请 AI 列出具体文件位置、已脱敏的路由类型和建议改动。明确要修复的项目后再执行，保留其他键、hooks、MCP 和项目配置；切回官方路径不能只凭删除一行就宣告成功。
谁来做实际动作
AI 自动完成只读配置检查；在可控制的正确本地浏览器里读取检测结果；脱敏、判定状态、生成回执和指南；在当前工具允许时打开 HTML。
你手动完成确认使用资格、改时区与选定出口、选择实际浏览器、输入账号凭据、注册登录、提交申诉、处理退款或付款，决定具体修复范围。
条件触发才执行本地状态重置、代理或配置修改、浏览器设置调整、IPv6 处理；先明确问题、影响和备份，再执行并复测。

第一条防线 · 环境（社区经验为主）

环境准备：固定比纯净重要

社区复盘的共识：泄漏和跳节点比 IP 类型更常出事。天天在机场里切节点，IP 标签再漂亮也白搭；把设备、时区和出口固定下来，比花大钱买家宽有用。本节的步骤多数为社区经验，skill 质检只读取和记录这些状态，不会自动修改。

1. 时区：电脑和手机改成同一个支持地区

  1. Mac：系统设置 → 通用 → 日期与时间，关掉“使用你的当前位置自动设定时区”，手动搜 Taipei / 台北；再去 系统设置 → 隐私与安全性 → 定位服务 → 系统服务（详细信息），关掉“设定时区”。很多人漏这步——不关的话 Wi-Fi 定位会把时区拽回上海。
  2. iPhone：设置 → 通用 → 日期与时间，关掉“自动设置”，时区选台北；再到 设置 → 隐私与安全性 → 定位服务 → 系统服务，关掉“设定时区”。
  3. Windows：设置 → 时间和语言 → 日期和时间，关闭“自动设置时区”，选择 (UTC+08:00) 台北。
readlink /etc/localtime
# 结尾应为 Asia/Taipei

node -e "console.log(Intl.DateTimeFormat().resolvedOptions().timeZone)"
# 应输出 Asia/Taipei（未装 Node 可跳过）

为什么选台北：台湾在官方支持名单里，Asia/Taipei 又和北京时间同属东八区，作息不用改（选择理由为社区经验）。两端要对齐——电脑说自己在台北、手机说自己在上海，本身就是一对矛盾信号。改时区是为了消除环境自相矛盾，不是官方要求。

2. 出口 IP：先学会认机房 IP，再谈纯净

词人话解释为什么重要
出口 IP网站看到的你的 IP，也就是代理节点的 IPClaude 用它判断你在哪个国家
ASN 类型这个 IP 归谁管：ISP / Residential 是家庭宽带，Hosting 是机房机房 IP 往往成百上千人共用，风控更敏感
TUN 模式代理软件装一张虚拟网卡，接管全部流量不靠程序自觉读代理设置，终端里的 Claude Code 也走同一个出口
系统代理代理软件在系统设置里登记一个 127.0.0.1 之类的地址程序可以不理它，还会留下用了代理的痕迹
WebRTC / DNS 泄漏浏览器或系统绕过代理直接暴露真实 IP，或用国内 DNS 解析挂着境外节点却漏出国内 IP，是很多人真正被封的原因

判断方法：打开 ipinfo.io ↗ 或 ping0.cc ↗，看 country、city、org。机房 IP 像群租房的门牌号，一个地址后面挤着几千号人；住宅 IP 像你自己家的门牌号。看到 org / ASN 类型写着 Hosting、某某 Cloud，先换出口，别急着登 Claude。换成住宅 IP 后再查一次，ISP 一栏应是真实的家庭宽带运营商名字。

方案适合谁优点坑
固定一个机场节点先活下来零成本机房 IP、多人共用，只算最低配
订阅式静态住宅 IP大多数新手ASN 为 ISP，订阅链接直接导入代理客户端不同档位 IP 质量不同，买完要自己验
代理式静态住宅 IP愿意多折腾一步便宜、独享、可选国家多只给 SOCKS5 / HTTP 账号，要配链式代理；需要 KYC
自建 VPS 独享出口会 SSH、能自己搭出口只有你一个人用仍是机房 IP（Hosting），风险高于住宅
独立电脑 + 固定家宽重度用户最稳成本最高
  • 固定单节点：只留这一个节点，关掉“自动选择 / 按延迟自动切换”。延迟低不代表要轮询。
  • 买完先验：在 ping0.cc / ipinfo.io 确认国家对、类型是 ISP 不是 Hosting；不好用先找商家换，别默认每个节点都能过 Claude。
  • 全程同线路：注册、登录、付款、日常使用都走这一条出口。
  • 自建 VPS 避开国内大厂的海外区：IP 显示在境外，hostname 和 ASN 却还带着国内大厂，是明显的矛盾信号。

适用边界：普通机场看视频、刷网页完全够用。你是重度 AI 用户、想认真养主力号，这一层才值得花钱。社区方案没有官方背书，本指南不推荐具体商家，选哪家自己验。

3. 代理客户端：开 TUN，关系统代理

为什么一定要 TUN：系统代理靠程序自觉遵守，程序可以不理；TUN 用虚拟网卡接管所有 TCP / UDP 流量，终端里的 Claude Code 也走同一出口，不用做任何配置。Mac / Windows 社区常用 Clash Verge Rev ↗（只从 GitHub 官方仓库下载）；Surge 用户打开“增强模式”，系统代理保持关闭，效果相同。

  1. 导入订阅：“订阅”页粘贴链接并导入，点选这个配置。
  2. 先用系统代理跑通一次：浏览器能打开 ipinfo.io，说明订阅没问题。
  3. “设置”里安装“服务模式”（会要求输入电脑密码），这是不开管理员身份也能开 TUN 的前提。
  4. 打开“TUN 模式”，然后关掉“系统代理”，避免两套代理叠在一起。
  5. “代理”页切到“全局”，选中固定节点；用 Claude 期间不建议规则模式，分流规则写错就会漏。
  6. 新开一个终端窗口再做下面的自检——老窗口可能还带着旧的代理变量。

4. 登录 Claude 前的 5 项自检

每次换节点、重装系统、换电脑之后都完整做一遍；任何一项不过，先别登录。这些检查项与skill 质检对应，可以让 AI 代查并生成回执。

  1. 查出口 IP。

    浏览器打开 ipinfo.io / ping0.cc，或在终端运行 curl -s ipinfo.io。看 country、city、org：国家固定，城市别每次变，org 不是一眼能认出的机房。

  2. 查 WebRTC 泄漏。

    打开 browserleaks.com/webrtc ↗，页面里不能出现你的国内真实 IP。开了 TUN 一般不会漏；还漏就检查浏览器 WebRTC 设置。

  3. 查 DNS 泄漏。

    打开 browserleaks.com/dns ↗，结果里不应出现中国的 DNS 服务器。TUN 默认接管 DNS；仍看到国内 DNS，就检查客户端的 DNS 与劫持配置。

  4. 查系统代理残留。 
    # macOS：期望三行都是 0；出现 1 说明系统代理还开着
scutil --proxy | grep -E "HTTPEnable|HTTPSEnable|SOCKSEnable"

# Windows 不要运行 scutil。让 skill 读取 WinINet 开关；
# 也可以在「设置 → 网络和 Internet → 代理」里看“使用代理服务器”是否打开。
  5. 清掉终端里的代理与中转残留。 
    env | grep -iE "proxy|anthropic|claude"
grep -iE "proxy|ANTHROPIC" ~/.zshrc ~/.bashrc ~/.profile ~/.zshenv
# macOS hosts
grep -iE "anthropic|claude" /etc/hosts
# Windows hosts（PowerShell，先备份再改）
# Select-String -Path "$$env:SystemRoot\System32\drivers\etc\hosts" -Pattern "anthropic|claude"
npm config get proxy
npm config get https-proxy
git config --global --get http.proxy
git config --global --get https.proxy
cat ~/.claude/settings.json
cat ~/.claude/settings.local.json

    重点找 ANTHROPIC_BASE_URL 与 hosts 里的 anthropic/claude 域名行：用过镜像站、Claude Code Router 或各种中转的，这两处常有残留。shell 与 settings 里找到就删掉那一行；hosts 的修改需要管理员权限，动手前先备份原行。Windows 还要看 PowerShell 配置里的 $$env:HTTPS_PROXY 与 $$env:ANTHROPIC_BASE_URL。改完新开终端复测。

可选加固：关闭 IPv6（先保存原值，可随时恢复）
  • 不少代理配置只接管 IPv4，IPv6 可能直连漏出去。确认未接管后再决定是否关闭，须针对实际的 Wi-Fi / 网线服务操作。
  • macOS 关闭：networksetup -setv6off Wi-Fi（网线改为 Ethernet）；恢复：networksetup -setv6automatic Wi-Fi。Windows 不要套用这条命令；若确认要关，在对应网卡属性里取消“Internet 协议版本 6”，并先记下原来是否勾选。skill 默认不改 IPv6，此步为你手动决定。
  • 单次 IPv6 查询失败不能证明已关闭，也没有证明不泄漏；改动后复测。

5. 设备纪律：一号、一人、一台设备

  • 一个号、一个人、一台常用电脑；同事想借也不借——同一台设备登多个账号，是这轮封号潮里最扎眼的特征之一。
  • 浏览器单独建一个资料，只用来登 Claude；单号不需要指纹浏览器。
  • Claude Code 授权时用下面的命令登录，把它给出的授权链接复制到专用浏览器里打开，免得默认浏览器带着别的环境去授权： 
    # macOS / Linux 终端
BROWSER=false claude

# Windows PowerShell
$$env:BROWSER = "false"; claude
  • 定期去 claude.ai → Settings → Account 按官方说明查看活动会话，发现陌生登录由你决定是否终止（会让相应设备登出）。入口见官方会话说明 ↗。
  • 手机端能不用就不用，减少设备分叉；这是社区复盘的经验，不是官方要求。

第二条防线 · 账号与支付（社区经验为主）

账号与支付：账单信用常常比 IP 更重

1. 邮箱与手机号

  • 用你自己能长期控制的 Gmail / Outlook / Proton，别用一次性邮箱，也别买二手谷歌邮箱——它可能已经和一批被封的号绑过。
  • 验证邮件要在同一个代理环境、同一个专用浏览器里点开。注册阶段翻车最多的就是这一步。
  • 手机号：国内号、接码平台号能过注册，但社区反馈后续容易被标记；有条件用你能长期控制的支持地区号码。

2. 订阅节奏：按周走，别一天登顶

新号加新卡直接开 Max，是风控里最显眼的一类。社区观察到的窗口大致在注册或充值后 24～72 小时；额度进度条变黄就停——这条经验来自被封过多个号的人，做起来一分钱不花。

  1. 准备一个能正常付款的 Apple ID（社区常用美区 ID + 官方礼品卡，账单国家和出口尽量一致）。
  2. iPhone 下载官方 Claude App，用同一个 Anthropic 账号登录。
  3. 在 App 里升级到 Pro / Max，走苹果内购，不要跳回网页绑卡。
  4. 订阅成功后，电脑端用同一账号登录。

贵一点，但号没了至少还能找苹果退款。同一个苹果账号第一次申请退款往往有戏，再封就不一定了，别把退款当成稳定现金流。

5. 隐私开关

打开 claude.ai 的隐私设置，按你的意愿关掉帮助改进 Claude 的开关。按官方文档，关掉后会话保留 30 天，开着是 5 年。它防不了封号，只是少交一份样本。

第三、四条防线 · 开始使用之后

日常需要你留意的事情

  1. 保存账号通知，留意陌生会话。官方入口

    在 Settings → Account 中按官方会话说明查看活动会话。发现不认识的设备时由你决定是否退出该会话；这会让相应设备登出。密码、token、cookie 不共享给他人或提交到检测站。

  2. 触顶就等，别绕。

    用量受限时查看 Usage 的重置时间，按官方用量说明处理。限额不等于封号，换号绕过限制才像滥用。社区经验补充：新号前两周收着点用、额度变黄就停（见订阅节奏）——这些是社区复盘，不是官方规则。

  3. 只用官方客户端，不把订阅接到第三方工具。社区经验

    日常用 claude.ai、官方桌面端、官方 Claude Code。把 Pro / Max 的登录授权接到第三方 CLI 工具或中转，是这轮封号潮里明确的高发情形；要用第三方工具，按量走官方 API 另算。长期中转的残留清不掉时，服务端一看请求就知道你没走官方。

  4. 网络变更后检查，资料另存备份。

    更换网络工具、出口或浏览器设置后再运行检查。项目和重要成果保存在自己的工作目录，代码放本地 Git，别让项目只存在 Claude 的云会话里。本地状态归档可能包含凭据和会话，保留在私有目录，不上传公开空间。

  5. 内容别碰红线，语言不用担心。

    反编译、大规模渗透、勒索代码这类，别拿个人订阅硬刚。中文提问本身不是封号原因（社区复盘不支持这个说法），但别在系统提示或 CLAUDE.md 里写自己人在哪个城市——提示词会随请求发出去。

  6. Claude Code 遥测开关（可选）。官方开关

    在 ~/.claude/settings.json 的 env 里可关闭非必要上报，均为官方文档开关：

    {
  "env": {
    "DISABLE_TELEMETRY": "1",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1"
  }
}

    副作用（官方文档写明）：会同时关掉功能旗标，Remote Control 可能用不了，属正常现象。这是隐私偏好，不等于“防封通过”。不要把 ANTHROPIC_BASE_URL 指到第三方，不要改客户端二进制、不要用魔改版。详情见官方数据使用说明（页脚入口）。

这些说法，可以少信（社区流传 vs 可查证程度）
说法怎么看
中文提问、中文输入法决定生死无公开证据；语言不是判决指标，网络指纹和调用频率才是。别把地理位置写进提示即可。
充得越多越容易封不成立；高档订阅叠加虚拟卡和新号才危险，免费号也有第二天被封的。
研究员号、数学论文号更稳未验证；别把新号的第一件事设计成表演。
找人代过身份验证欺诈。官方报告点名：疑似在不受支持地区运行的账号可能被要求本人真实证件验证，不通过就封，环境配得再好也绕不过去。
拼车、低价成品号、封号包换使用政策明确禁止，拼车会一锅端，成品号支付链出事全员连坐。
家宽、老 Gmail、固定时区有官方背书都没有。官方可查的封号理由只有：反复违反使用政策、从不支持的地点创建账号、违反服务条款。

出发前清单

复制到备忘录，每次换节点、换电脑、重装系统后逐项核对；与 skill 回执的判定一一对应。
